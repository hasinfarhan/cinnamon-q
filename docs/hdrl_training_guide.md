## Overview

The HDRL agent is a PPO (Proximal Policy Optimization) reinforcement learning model that synthesizes three data modalities:
- **Technical Analysis**: Price/Volume (OHLCV)
- **Fundamental Analysis**: Developer activity, Community stats
- **Sentiment Analysis**: LLM-scored utility vs. hype

The agent learns to allocate portfolio weights across 6 crypto assets (BTC, ETH, SOL, LINK, UNI, AAVE) to maximize the Sortino Ratio (risk-adjusted return with downside focus).

## Training Workflow

### Step 1: Prepare Training Data

Ensure you have the complete dataset with all three modalities:

```bash
# Generate sentiment data (if not already done)
python scripts/09_generate_sentiment.py
```

**Expected Output:**
- File: `data/processed/crypto_training_data.parquet`
- Size: ~9-10 MB
- Rows: ~147,000
- Columns: 13 (including `utility_score`)

### Step 2: Start Training

```bash
# Optimized training (uses all CPU cores + GPU)
python scripts/10_train_hdrl_optimized.py
```

**What Happens:**
1. **Hardware Detection**: Detects GPU and CPU cores
2. **Environment Setup**: Creates 16 parallel environments
3. **Model Initialization**: PPO with 512x512x512 network
4. **Training Loop**: 
   - Collects data from 16 parallel environments
   - Updates model every 32,768 steps (2048 * 16)
   - Saves checkpoints every 100k steps
   - Evaluates and saves best model
   - **Early stopping** if no improvement for 10 evaluations

**Expected Training Time:**
- 10M timesteps: ~1 hour (RTX 4070 Ti Super)
- 5M timesteps: ~30 minutes
- Early stopping may finish sooner

### Step 3: Monitor Training

**Terminal Output:**
Watch for increasing `ep_rew_mean` (episode reward mean):
```
| rollout/                |             |
|    ep_rew_mean          | 2.62e+03    |  ← Should increase over time
|    explained_variance   | 0.962       |  ← Should be > 0.9
```

**TensorBoard (Optional):**
```bash
# In another terminal
tensorboard --logdir logs/hdrl_training_optimized/tensorboard

# Open browser: http://localhost:6006
```

**Key Metrics to Watch:**
- `ep_rew_mean`: Should increase (target: >2000)
- `explained_variance`: Should be >0.9
- `value_loss`: Should decrease
- `policy_gradient_loss`: Should stabilize

### Step 4: Training Completion

**Successful Training Output:**
```
✓ Training completed successfully!
✓ Final model saved to: models/hdrl_optimized/final_model.zip
✓ Normalization stats saved to: models/hdrl_optimized/vec_normalize.pkl
```

**Files Created:**
- `models/hdrl_optimized/final_model.zip` - Trained model
- `models/hdrl_optimized/vec_normalize.pkl` - Normalization statistics
- `models/hdrl_optimized/best_model/` - Best model during training
- `models/hdrl_optimized/hdrl_crypto_optimized_*_steps.zip` - Checkpoints
- `logs/hdrl_training_optimized/` - Training logs

## Model Versioning

### Why Version Models?

- **Reproducibility**: Track which model version is in production
- **Rollback**: Easy to revert to previous working version
- **Comparison**: Compare performance across versions
- **Compliance**: Audit trail for financial systems

### Versioning Workflow

#### 1. After Training - Create Versioned Copy

```bash
# Determine version number (e.g., v1.0, v1.1, v2.0)
VERSION="v1.0"

# Create versioned copies
cp models/hdrl_optimized/final_model.zip \
   models/hdrl_optimized/final_model_${VERSION}.zip

cp models/hdrl_optimized/vec_normalize.pkl \
   models/hdrl_optimized/vec_normalize_${VERSION}.pkl
```

#### 2. Document Version in VERSIONS.md

Edit `models/hdrl_optimized/VERSIONS.md`:

```markdown
## v1.1 (New Version)

- **Training Date**: 2025-01-XX
- **Training Timesteps**: 5,944,320
- **Performance Metrics**:
  - Episode Reward Mean: 2,620
  - Explained Variance: 0.962
- **Changes from v1.0**:
  - Increased batch size to 4096
  - Added early stopping
- **Status**: ✅ Ready for production
```

#### 3. Update Configuration (If Switching Versions)

Edit `config.yaml`:

```yaml
strategies:
  - name: "crypto_hdrl_v1"
    signal: "ppo"
    params:
      model_path: "models/hdrl_optimized/final_model_v1.1.zip"
      vec_norm_path: "models/hdrl_optimized/vec_normalize_v1.1.pkl"
```

### Semantic Versioning Guidelines

- **Major (v2.0)**: Architecture changes, new data modalities
- **Minor (v1.1)**: Hyperparameter tuning, more training data
- **Patch (v1.0.1)**: Bug fixes, minor improvements

## Troubleshooting

### Issue: Missing vec_normalize.pkl

**Symptom:**
```
FileNotFoundError: Normalization stats not found: models/hdrl_optimized/vec_normalize.pkl
```

**Solution:**
```bash
# Regenerate normalization statistics
python scripts/recover_stats.py
```

This script replays the training data through VecNormalize to calculate statistics.

### Issue: Model File Not Found

**Symptom:**
```
FileNotFoundError: Model not found: models/hdrl_optimized/final_model.zip
```

**Solutions:**
1. **Check if training completed:**
   ```bash
   ls -lh models/hdrl_optimized/
   ```

2. **Use a checkpoint:**
   ```bash
   # Find latest checkpoint
   ls -t models/hdrl_optimized/hdrl_crypto_optimized_*_steps.zip | head -1
   
   # Copy to final_model.zip
   cp models/hdrl_optimized/hdrl_crypto_optimized_4800000_steps.zip \
      models/hdrl_optimized/final_model.zip
   ```

3. **Use best_model:**
   ```bash
   cp models/hdrl_optimized/best_model/best_model.zip \
      models/hdrl_optimized/final_model.zip
   ```

### Issue: Normalization Drift

**Symptom:**
Model predictions seem wrong or inconsistent.

**Cause:**
Live data is not being normalized using training statistics.

**Solution:**
Ensure `PPOStrategy` loads `vec_normalize.pkl` and applies it:
```python
# In PPOStrategy.get_target_portfolio()
norm_obs = self.norm_env.normalize_obs(raw_obs)  # CRITICAL!
```

### Issue: Training Too Slow

**Solutions:**
1. **Reduce parallel environments:**
   ```python
   # In scripts/10_train_hdrl_optimized.py
   n_envs = 8  # Instead of 16
   ```

2. **Reduce total timesteps:**
   ```python
   total_timesteps = 5_000_000  # Instead of 10M
   ```

3. **Use CPU instead of GPU:**
   ```python
   device = "cpu"  # MLP policies train faster on CPU
   ```

### Issue: Out of Memory

**Solutions:**
1. **Reduce batch size:**
   ```python
   batch_size = 2048  # Instead of 4096
   ```

2. **Reduce network size:**
   ```python
   policy_kwargs = dict(
       net_arch=dict(pi=[256, 256], vf=[256, 256])  # Smaller network
   )
   ```

3. **Reduce parallel environments:**
   ```python
   n_envs = 8  # Instead of 16
   ```

### Issue: Poor Training Performance

**Checklist:**
1. **Data quality:**
   - Verify `crypto_training_data.parquet` has all columns
   - Check for NaN values
   - Ensure data is recent

2. **Reward signal:**
   - Check if `ep_rew_mean` is increasing
   - If not, reward function may need tuning

3. **Hyperparameters:**
   - Learning rate too high/low
   - Network too small/large
   - Batch size inappropriate

4. **Early stopping:**
   - May be stopping too early
   - Increase `min_evals` in early stopping callback

## Best Practices

### 1. Training

- **Always version models** after training
- **Document hyperparameters** in VERSIONS.md
- **Track performance metrics** for comparison
- **Use early stopping** to prevent overfitting
- **Save checkpoints** regularly (every 100k steps)

### 2. Model Management

- **Never commit model files** to git (use .gitignore)
- **Track metadata** in git (VERSIONS.md, README.md)
- **Use semantic versioning** (v1.0, v1.1, v2.0)
- **Keep production model** as `final_model.zip` for simplicity
- **Archive old versions** to cloud storage

### 3. Deployment

- **Test model loading** before deployment
- **Verify normalization stats** are loaded
- **Monitor first few predictions** closely
- **Keep previous version** available for rollback
- **Document deployment** in VERSIONS.md

### 4. Monitoring

- **Track portfolio performance** in database
- **Log all predictions** for analysis
- **Compare model versions** regularly
- **Set up alerts** for unusual behavior
- **Review TensorBoard logs** periodically

### 5. Data Pipeline

- **Keep data fresh**: Update training data regularly
- **Validate data quality**: Check for missing values, outliers
- **Version datasets**: Track which data version was used for training
- **Document data sources**: Note where data came from
